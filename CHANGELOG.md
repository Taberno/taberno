## [Unreleased]

### Added
- Printable packing slips & invoices for orders. Each order (Admin → order → Print) has a **packing slip** — order number, ship-to address, items with quantity/options and picking notes, **no prices** (it's read by warehouse help and gift recipients) — and an **invoice** — seller block, line items with unit prices, subtotal, discount, shipping, tax and total, and payment status. A **bulk print run** (Orders → "Print packing slips") renders every unfulfilled order for a day as one document, one order per page, so a morning's fulfilment is a single print job (capped at 200, and it says so). It's plain print-view HTML with a `@media print` stylesheet — the browser's own print dialog makes the PDF, so there's **no PDF library or new dependency** — and everything renders from the order's frozen values, so a reprint after a price change still shows what was paid. New **Business name & address** settings (Settings → Store) feed the invoice's seller block; the admin warns when they're still empty (VAT number comes from Settings → Tax).
- WooCommerce migration keeps your SEO: the importer now records every product, category and page's **old WooCommerce URL** and serves a **301 redirect** from it to the new one — so a migrated shop keeps its Google rankings and inbound links instead of 404ing them. Handles the old URL shapes (`/product/<slug>/`, `/product-category/<slug>/`) and the `/?p=<id>` form Woo serves every object at, with or without a trailing slash. A real page always wins over a redirect (create a page at an old path and it takes over), system paths (`/admin`, `/checkout`, `/cart`, …) are never redirected, and re-running an import updates rather than duplicates. Manage and manually add redirects — with a hit counter showing they're working — under **Settings → Redirects**.
- "Request a feature" link in the admin sidebar footer — opens a pre-filled GitHub issue (enhancement label, a short title/body template) so store owners can suggest features without any API token or account setup on the store's side.
- Visual page builder with live preview. Every page (Admin → Pages) is built from **reorderable sections** with a **live preview** pane beside the editor — an iframe of your real storefront that re-renders as you add/reorder sections, change colours or pick a collection, with **Desktop/Mobile** width toggles and manual refresh. The editor is a two-pane layout — a collapsible left panel holds the page title, SEO, publish controls **and** the sections; the preview fills the right-hand side and can be expanded to full width. Sections **reorder by drag-and-drop** (or keyboard up/down buttons).
  - **Product & collection page templates**: shared **Product page** and **Collection page** templates (Admin → Page templates) render builder sections on every product/collection page below the core content, **plus** each individual product and collection can add its own sections ("Edit page sections" on the product/collection editor) — the global template renders first, then the item's own.
  - **Reusable sections** (Admin → Reusable sections): build a set of sections once and drop it onto any page with the **Reusable block** section — edit the block and every page using it updates. Blocks are edited in the same builder (with live preview); a missing/deleted block simply renders nothing.
  - **Draft / publish per page**: section edits are saved as a **draft** and previewed without going live; **Publish** pushes them to the storefront, **Discard** reverts to the published version. The live site always renders the published sections; an "unpublished changes" badge shows when a draft is pending. The preview goes through the exact storefront render pipeline (a read-only, admin-only, CSRF-exempt endpoint that renders the draft), so what you see is what ships; marketing pixels are suppressed while previewing.
  - **Sections are schema-driven**: each type declares its settings once (in a central registry) and the editor form, defaults and validation are generated from that — adding a section is a schema entry plus a theme partial. Section data is whitelisted and defaulted **server-side** on save (unknown types/fields never reach the DB).
  - **Section library**: **Hero** (heading, subheading, background image, button, alignment) and **Featured products** (choose a collection/count/columns; products fetched live) both with **background/text colour**; **Gallery** (image grid), **Testimonials** (quote/author/role/avatar), **Logo row** (logos with optional links), **Slideshow** (image slides with heading/subheading/button, arrows + dots + optional auto-advance), **FAQ** (accordion, links allowed in answers), **Newsletter** (signup wired to the built-in capture), **Video** (paste a YouTube/Vimeo link → embedded player), **Map / contact** (address + phone/email + a keyless embedded Google map) and **Spacer / divider**; the **Hero** also gained an eyebrow label and an image-beside-text (split) layout — each with add/reorder/remove of items and optional background/text colour; plus text, image, image + text, call-to-action, and two-column — **every content section now has background + text colour controls** and paints as a full-width band. Multi-item sections are powered by a **repeater** field type (one level of nested items). Colour fields offer your live **site colours** (Highlight/Primary/Background) as theme tokens — so a section follows a later brand-colour change rather than freezing a hex — with a custom-colour option, validated server-side so they can't break out of the inline style.
  - **Set any page as the home page** (a checkbox on the page) — it renders at your store root `/` (its own slug 301s there), replacing the theme's default home; untick or delete it and the default home returns. Featured-products and other dynamic sections now resolve on any page. Works in both bundled themes.
- B2B / wholesale (customer groups, group pricing & pay-on-account). Group customers (e.g. Trade, Wholesale) under Customers → Customer groups, then assign each customer to a group. A group can carry: a **store-wide % discount** (applied at the cart/checkout as its own line, so what the customer pays — not just what's shown — is reduced) and a **tax display override** (force inc- or ex-tax prices for that group, e.g. ex-VAT for trade). A group can also be flagged **"Allow invoicing"** with optional **net payment terms (days)**: those customers get a **"Place order — pay by invoice"** option at checkout that places the order **unpaid** (no card taken) — stock is still reserved, an **invoice email** is sent (with the amount due and a due date derived from the terms), and the order sits `pending` in the admin with an "on account" panel until the merchant marks it paid. The invoice option and discount are enforced server-side (never trust the button), and the order carries a reserved `accounting_ref` so a future accounting integration (e.g. Xero, QuickBooks) can sync invoices idempotently. Works in both bundled themes.
- Bookable delivery/collection slots: any shipping rate (delivery or collection) can require the customer to book a **date + time window** — set the available weekdays, time windows, lead time, booking horizon and blackout dates on the rate (Shipping → rate → "Customers book a date & time"). At checkout, choosing a scheduled option reveals a date/time picker populated with server-computed valid dates and validated server-side; the booking is stored on the order and shown in the admin order view, confirmation email and success page. A product can be flagged **"Needs a booked delivery/collection date"**, which requires any order containing it to choose a scheduled option and book a slot. (Slots are unlimited — they don't sell out yet.)
- Local pickup / collection: a shipping rate can now be a **collection point** (Shipping → a zone → rate type "Collection / pickup") carrying an address and opening-hours/instructions, at any price (usually free). Add one rate per location for multiple collection points. At checkout it appears alongside the delivery options; choosing it hides the delivery-address fields, and the collection address + hours are snapshotted onto the order and shown in the admin order view, the confirmation email, and the order-success page.
- Pre-orders: a product with an availability window can additionally allow **pre-orders** (Product → Availability → "Allow pre-orders"). During the upcoming window customers can order it (sold against stock) — the storefront shows an enabled **Pre-order** button and a "ships from …" note, and each order line is flagged as a pre-order with its ship date in the admin order view and the confirmation email, so fulfilment can be held until then. With pre-orders off, an upcoming product just shows "Coming soon" and stays unpurchasable.
- Product calendar (availability windows): a product can be given an optional **Available from** / **Available until** date. It stays visible the whole time, but is only purchasable between those dates — outside the window the add-to-cart button is disabled (showing "Available from …" or "No longer available") and the store enforces it server-side — both at add-to-cart and re-checked at checkout — so a scheduled/seasonal drop can go up early and open/close on its own. Product cards show a "Coming soon" / "Unavailable" badge. Works in both bundled themes.
- Usage metering & limits (hosted groundwork): the app measures products, unique monthly visitors and upload storage, and can enforce per-store limits **injected by the host** (via settings or env — `limit_products` / `LIMIT_PRODUCTS`, etc.). Over-limit product creation is blocked admin-side (never the storefront), with an optional `upgrade_url`. No limits are set by default, so a standalone/self-hosted install stays unlimited. Pricing, plans and billing deliberately live in the hosted control plane, not in this open-source app.
- Managed email (hosted groundwork): in `CLOUD_MODE`, email settings come from the environment and take precedence over the store's stored settings — `EMAIL_PROVIDER`, `EMAIL_FROM_NAME`, `EMAIL_FROM_ADDRESS`, `RESEND_API_KEY`, `SMTP_HOST`/`SMTP_PORT`/`SMTP_USER`/`SMTP_PASS`/`SMTP_SECURE`, plus a new `EMAIL_REPLY_TO` that adds a `Reply-To` header. An unset/empty variable falls back to the stored value, so the control plane can own deliverability without wiping a store's own config. On managed hosting Settings → Email becomes a read-only summary (sending address, deliverability handled, change it from the Cloud dashboard) instead of the provider/credential form. **Self-hosted installs are unaffected** — with `CLOUD_MODE` off the environment is ignored entirely and behaviour is unchanged.
- Taberno Cloud single sign-on (hosted groundwork): in `CLOUD_MODE`, a new `GET /admin/cloud-session` accepts a short-lived, single-use token minted by the control plane and signs the bearer straight into this store's admin — so "Open admin" in the Cloud dashboard lands them in their shop instead of a login/setup form, and a hosted customer keeps one credential (their dashboard) rather than a second per shop. The token is signed with a **per-store** secret (`CLOUD_AUTH_SECRET`, never the shared `CLOUD_SECRET`) and verified in constant time; it must be unexpired (60s life), match this store's `STORE_ID`, and be unused (each `jti` is recorded once). The first such sign-in creates the owner account (no `/admin/setup` step) with **no password** — they can set one later from their account page to also sign in directly. **Self-hosted installs are unaffected** — with `CLOUD_MODE` off the route does not exist at all.
- Mega menus: any header navigation link can now open a mega menu, configured under Navigation. Each mega menu holds any number of columns, and every column is one of three types — plain **links**, **categories** (pick a collection from a dropdown, with an optional picture), or **products** (pick a collection + how many to show, displayed as thumbnails, a list with images, or a text-only list, with an optional "Show more" link to the collection). The panel is centred at the content width, and each menu can lay its columns out automatically or in a fixed number of columns per row. Works in both bundled themes (opens on hover with keyboard focus support on desktop, expands inline on mobile).
- Nova theme: a second bundled storefront theme (activate it in Admin → Themes) sharing Linen's full template set, restyled via its own colour tokens and stylesheet.
- Blog: a full blog built on the pages/CMS engine — posts use the same page-builder sections, plus a featured image, author byline and publish date (with scheduling). Chronological `/blog` index (paginated), `/blog/:slug` post pages with BlogPosting structured data, an RSS feed at `/blog/rss.xml`, and posts in the sitemap. Managed under a new admin "Blog" section.
- Automatic discounts (no code needed), managed under Promotions → Automatic: an order discount (% or fixed off over an optional spend threshold) and buy-X-get-Y (BOGO — buy N get M at X% off, targeting all products or a collection), each with an optional date window. Applied at the cart and shown as their own lines; order-level discounts take the better of code vs automatic, BOGO stacks. (Free-shipping-over-X already exists as a shipping rate type.)
- Related & upsell products: the product-page "You may also like" is now genuinely related (products sharing a collection, topped up so the row is never thin) instead of random, with an optional manual per-product picker in the admin; plus a "You might also like" recommendations row on the cart page based on what's in the cart (AOV).
- Product reviews: star ratings + reviews on product pages (open submission with an automatic "Verified purchase" badge when the email matches a paid order), average rating on product cards, admin moderation (approve/reject, delete, with a toggle between approve-first and publish-instantly), and schema.org Product/AggregateRating structured data for search rich results.
- Abandoned-checkout recovery: emails customers who start checkout but don't pay, once, after a configurable delay (Settings → Store; blank/0 = off), with a token-signed one-click unsubscribe. Editable `abandoned_cart` template.
- Order CSV export from the orders admin.
- Low-stock alerts: emails the store owner when a product variant drops to/below a configurable threshold after a paid order (Settings → Store; blank to disable, 0 = only when sold out). Editable `low_stock` email template.
- Promo banners: a scheduled, site-wide announcement bar managed under Promotions → Banners, with an optional link/CTA, a copy-to-clipboard discount-code pill, custom colours, visitor dismiss, and start/end dates (newest live banner wins).
- Configurable cart word (Cart / Basket / Bag) that drives the label, URL and nav together, with no restart.
- Zero-config "direct" email transport (MX delivery, best-effort) alongside SMTP and Resend.
- Order fulfilment workflow: mark shipped, tracking number, status changes, and the `order_shipped` email.
- Refund / cancellation from the order admin (Stripe & PayPal).
- Merchant new-order email notification.
- Customer password reset flow.
- Database backup/restore scripts (`npm run db:backup` / `db:restore`) and a `/health` endpoint.

### Changed
- The admin "Discounts" section is now "Promotions", with discount codes and banners as tabs within it.
- Inventory is now decremented on paid orders, with a pre-checkout stock re-check.
- Storefront assets (htmx, Alpine, Inter font) are self-hosted — no third-party runtime requests.
- WooCommerce import skips WooCommerce's own system pages (cart, checkout, my-account, shop, …).

### Fixed
- Managed hosting: the Import / Export page now offers the **full whole-store export and import** (the same `.zip` backup/transfer as a self-hosted install) — previously cloud stores only saw the WooCommerce importer, so there was no way to bring a Taberno store in or, more importantly, to take your store **out** to self-host it. Export is back on the page for everyone (it's your data — no lock-in); on Cloud a note also points to the dashboard, where nightly backups happen automatically.
- Admin styling left broken by the earlier Tailwind removal (status badges, utility classes).
- Theme-editor image upload no longer reloads the page and discards unsaved edits.
- Order confirmation emails rendered blank totals.
